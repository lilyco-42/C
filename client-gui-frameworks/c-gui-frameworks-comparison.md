## 1. Nuklear

| 项目 | 内容 |
|------|------|
| **仓库** | https://github.com/Immediate-Mode-UI/Nuklear |
| **协议** | Public Domain / MIT |
| **最新版本** | v4.13.2 (2026 年 3 月) |
| **语言** | **ANSI C (C89)** |
| **设计范式** | 即时模式 (IMGUI) |
| **代码量** | ~18K 行，单头文件 (`nuklear.h`) |
| **依赖** | **零**（不需标准库） |

### 概述

Nuklear 是目前最活跃的纯 C 即时模式 GUI 库。单个头文件即可集成，不依赖任何外部库甚至标准库。通过预处理器宏模块化编译，内置 ~15 种核心控件 + 10+ 渲染后端（OpenGL、Vulkan、DirectX、Metal、SDL 等）。

### 优势

- **零依赖** — 连 libc 都不需要，纯裸机环境可用
- **单头文件** — 复制 `nuklear.h` 即可开始使用
- **极高可移植性** — 从 8 位 MCU 到桌面 PC，约 12+ 种渲染后端
- **完全内存控制** — 固定内存池，无隐藏 malloc/free，实时/嵌入式可预测
- **完全可换肤** — 每个视觉元素均可自定义主题
- **模块化编译** — 通过预处理器宏选择只编译你需要的功能
- **UTF-8 支持**
- **C89 兼容** — 任何 C 编译器均可编译
- **线程安全**

### 劣势

- **即时模式开销** — UI 每帧重建，静态 UI 效率低于保留模式
- **无原生控件** — 无 OS 原生外观，控件行为与系统不一致
- **控件较少** — 比 FLTK/Qt 少得多
- **文本输入简陋** — 依赖 `stb_textedit`，复杂 IME 输入法支持困难
- **可访问性差** — 无屏幕阅读器支持，无键盘导航框架
- **社区较小** — 资源和教程少于 Dear ImGui
- **原作者已停止开发** — 社区 fork 仍在活跃
- **页面撕裂** — 即时模式的状态可能滞后一帧

### 适用场景

- 游戏 HUD / 工具界面
- 嵌入式系统简单 UI
- 快速原型
- 已有 OpenGL/DirectX 项目需要轻量 UI 覆盖层

## 2. FLTK (Fast Light Toolkit)

| 项目 | 内容 |
|------|------|
| **官网** | https://www.fltk.org |
| **协议** | LGPL v2（含静态链接例外） |
| **最新版本** | v1.4.4 (2025 年 7 月) |
| **语言** | **C++**（避免模板/异常/RTTI） |
| **设计范式** | 保留模式 (Retained-mode) |
| **核心库大小** | ~114 KB |
| **首版发布** | 1998 年 |

### 概述

FLTK 是一个久经考验的轻量级 C++ GUI 工具包，自 1998 年开始开发。以极小体积（Hello World ~100KB）和轻量级 C++ 设计著称（不使用模板、异常、RTTI、namespace）。内置 ~60 种控件 + WYSIWYG 可视化设计器（FLUID） + OpenGL 原生支持。被 Foundry Nuke、Dillo 浏览器、Gmsh 等知名软件使用。

### 优势

- **体积极小** — 核心库仅 114 KB，静态链接后二进制很小
- **极稳定成熟** — 自 1998 年开发至今，v1.4.x 稳定
- **跨平台** — Windows / macOS / Linux (X11 & Wayland) / AmigaOS 4
- **OpenGL 原生集成** — `Fl_GL_Window` 让 3D 图形嵌入 GUI 简单直接
- **FLUID 可视化设计器** — WYSIWYG 拖放生成 C++ 代码
- **~60 内置控件** — 远多于 Nuklear/GuiLite
- **轻量级 C++** — 避免模板、异常、RTTI，学习曲线平缓
- **商业友好许可** — LGPL + 静态链接例外，无 GPL 污染
- **真实产品使用** — Nuke、Dillo、CinePaint、Gmsh、FLDIGI

### 劣势

- **非原生外观** — 自绘控件，不与 OS 主题一致
- **控件比 Qt/GTK 少** — 复杂应用仍显不足
- **非英语字体支持历史较差** — CJK 文字渲染曾有问题
- **自绘体系** — 圆角、动画、重叠控件等需大量自定义代码
- **无系统 API 抽象** — 非 GUI 功能常需平台特定代码
- **C++ 专属** — 无原生 C API
- **生态远小于 Qt**

### 适用场景

- 嵌入式 Linux 桌面（Tiny Core Linux 的默认 GUI）
- 小型、快速桌面工具/实用程序
- 科学/工程工具（有限元、医学影像）
- 需要 OpenGL 集成 + 轻量 GUI 的项目
- 二进制体积敏感的桌面应用

## 3. GuiLite

| 项目 | 内容 |
|------|------|
| **仓库** | https://github.com/idea4good/GuiLite |
| **协议** | Apache 2.0 |
| **语言** | **C++**（单头文件） |
| **代码量** | **~4,000 行**（`GuiLite.h` 单头文件） |
| **最小硬件** | **24MHz MCU + 9KB RAM + 29KB ROM** |
| **设计范式** | 极简保留模式 / UI 内核 |

### 概述

GuiLite 是目前最极致的轻量级 GUI 库 — 仅 4000 行 C++ 代码，却能在 24MHz Cortex-M0+ 上流畅运行。零动态内存分配，可以嵌入到 Qt、MFC、WinForms、Cocoa 等框架中作为加速渲染引擎。作者明确表示："我们不鼓励你直接使用 GuiLite"，而是希望开发者通过阅读其源码理解 GUI 原理并构建自己的框架。

### 优势

- **极致精简** — 仅 4-5K 行 C++，可合并为一个 `.h` + 一个 `.cpp`
- **零动态内存分配** — 所有对象栈/静态分配，运行时无 malloc/new
- **硬件需求极低** — 24MHz MCU + 9KB RAM + 29KB ROM
- **全平台** — iOS/Android/Windows/Linux/macOS/裸机 MCU
- **可嵌入其他 UI 框架** — 唯一支持注入 Qt/MFC/WinForms/Cocoa/Web 作为加速模块的框架
- **多语言业务逻辑** — 可用 Swift/Java/C#/Go/Python 写逻辑，GuiLite 只处理渲染
- **快速渲染** — 像素级绘图，无抽象层
- **Docker 支持** — 一条命令即可运行演示
- **教育价值高** — 代码量少，注释充分，适合学习 GUI 原理

### 劣势

- **控件极少** — 仅 ~8-10 个基础控件（按钮、标签、键盘、滑块、波形、列表、旋钮、编辑框）
- **非"完整"框架** — 更像一个 UI 内核/引擎，需要自己扩展
- **社区极小** — 用户量远小于 FLTK 和 Nuklear
- **C++ 专属** — 无纯 C API
- **无可视化设计器** — 仅有 VS Code 预览插件（功能有限）
- **无 GPU 加速** — 仅 CPU 帧缓冲区渲染
- **无 OS 原生主题**
- **项目哲学另类** — 作者希望你理解后自己造轮子，而不是直接使用

### 适用场景

- **极低资源 MCU**（STM32、Cortex-M0+）需简单显示
- **混合加速** — 在 Qt/MFC/Winform 中嵌入加速特定图形模块
- **学习 GUI 框架原理** — 代码量少，几天内读完
- **IoT 设备简单仪表盘**
- **对 ROM/RAM 极其敏感的项目**

## 4. microui

| 项目 | 内容 |
|------|------|
| **仓库** | https://github.com/rxi/microui |
| **协议** | MIT |
| **语言** | **C** |
| **代码量** | **~1,000 行** |
| **设计范式** | 即时模式 (IMGUI) |

### 概述

microui 是极简主义的 C 即时模式 GUI 库，仅有约 1000 行代码。设计哲学是"小到你可以完全理解和控制"。常与 raylib、SDL 结合使用，适合做调试覆盖层或简单的嵌入式 UI。

### 优势

- **极小** — 仅 ~1000 行代码，理解全部代码只需几小时
- **零依赖** — 纯 C，无外部要求
- **易于集成** — 与 raylib、SDL、GLFW 都可结合
- **MIT 许可**
- **设计干净** — API 简洁一致

### 劣势

- **功能极其有限** — 只有最基础的控件（窗口、按钮、滑块、文本框）
- **无渲染后端** — 需要自己实现（仅提供绘制接口定义）
- **无主题系统** — 外观全靠自己画
- **无字体支持** — 需要外部字体渲染
- **社区极小**
- **无高级控件** — 无列表、树、表格等

### 适用场景

- 调试 UI 覆盖层
- 极小嵌入式设备（对比 Nuklear 仍然太重时）
- 学习 IMGUI 基本原理
- 极简交互需求

## 5. SMGUI (State Mode GUI)

| 项目 | 内容 |
|------|------|
| **仓库** | https://codeberg.org/bzt/smgui |
| **协议** | MIT |
| **语言** | ANSI C |
| **代码量** | ~3,000 行，单头文件 |
| **设计范式** | **状态模式**（即时模式 × 保留模式混合） |

### 概述

SMGUI 是一个较新的 C GUI 库，作者对 Nuklear 不满意后自建。采用独特的"状态模式"——介于即时模式和保留模式之间：保留回调的复杂性但免去每帧重建的开销。支持 GLFW3/SDL2/X11/帧缓冲后端的单头文件库，包含字体连字、UTF-8 和多线程支持。

### 优势

- **新颖的混合设计** — 既无回调烦恼，也无 IMGUI 每帧重建开销
- **多后端** — GLFW3、SDL2、X11、fbdev（帧缓冲设备）
- **字体渲染好** — 支持连字和字距
- **UTF-8 支持**
- **多线程支持**
- **单头文件** — 易于集成
- **ANSI C 兼容** — `gcc -ansi` 即可编译

### 劣势

- **较新** — 用户基础和市场验证不足
- **生态几乎为零** — 无第三方控件/主题/资源
- **文档有限**
- **控件较少**
- **长期维护未证明**

### 适用场景

- 寻找 Nuklear 替代品
- 想要混合模式设计但不想用 C++
- 实验性/个人项目

## 选型建议

### 🏆 按场景推荐

| 场景 | 首选 | 备选 | 理由 |
|------|------|------|------|
| **超低资源 MCU**（<32KB RAM） | **GuiLite** | Nuklear | 9KB RAM 可运行，零动态内存 |
| **桌面工具（小型）** | **FLTK** | — | 稳定成熟 + FLUID 设计器 + OpenGL |
| **游戏 HUD / 工具覆盖层** | **Nuklear** | SMGUI | 即时模式天然适合游戏，零依赖 |
| **已有 OpenGL 项目** | **FLTK** | Nuklear | FLTK 内置 `Fl_GL_Window`，Nuklear 后端多 |
| **嵌入式 Linux 全栈 GUI** | **FLTK** | — | 114KB 库大小，Tiny Core Linux 已验证 |
| **调试覆盖层（简单）** | **microui** | Nuklear | 1000 行，极简集成 |
| **学习 GUI 原理** | **GuiLite** | microui | 4000 行代码，几天读完 |
| **在 Qt/MFC 中加速渲染** | **GuiLite** | — | 唯一专门支持嵌入的框架 |
| **寻求 Nuklear 替代** | **SMGUI** | — | 混合模式解决 IMGUI 痛点 |

### 一句话总结

- 要 **极致精简**（MCU 9KB RAM）→ **GuiLite**
- 要 **稳定成熟 + 可视化设计** → **FLTK**
- 要 **零依赖纯 C + 游戏 HUD** → **Nuklear**
- 要 **极简调试覆盖层** → **microui**
- 要 **IMGUI 替代品** → **SMGUI**

### 技术栈配合推荐

```
GUI 层选择        对应渲染/窗口层
──────────────────────────────────
Nuklear    →  OpenGL / Vulkan / DirectX / SDL
FLTK       →  内置 X11/Win32/Cocoa + OpenGL
GuiLite    →  CPU 帧缓冲 / 可嵌入 Qt/MFC
microui    →  raylib / SDL / GLFW
SMGUI      →  GLFW3 / SDL2 / X11 / fbdev
```
