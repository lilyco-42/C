## 1. Kore

| 项目 | 内容 |
|------|------|
| **官网** | https://kore.io |
| **协议** | ISC License |
| **最新版本** | 4.x (2025) |
| **语言** | C + 可选 Python 处理器 |
| **设计范式** | 事件驱动 (epoll/kqueue) |

### 概述

Kore 是一个 **安全优先、极致性能** 的 C Web 框架。采用 per-CPU-worker 模型 + 事件循环，在生产环境以单二进制部署。自带 privilege separation、seccomp/pledge 沙箱、隔离私钥管理，是目前 C 语言生态中最成熟的生产级框架。

### 优势

- **性能顶级** — 独立基准测试 572K req/s，所有框架中排名第二，吞吐量 (104 MB/s) 排名第一
- **安全纵深** — 强制 HTTPS、特权分离、seccomp/pledge 沙箱、密钥隔离进程、chroot 支持
- **零运行时依赖** — 编译为单一二进制，部署极简
- **热重载** — 模块可在不重启服务器的情况下动态更新
- **双语言支持 (v4+)** — 可用 C 或 Python 编写处理器
- **内置异步 PostgreSQL** — 数据库操作非阻塞
- **参数验证 / WebSocket / ACME 自动证书** 内置
- **资产(Asset)编译** — 支持 ETag + 304 缓存处理

### 劣势

- **仅限 Unix** — 不支持 Windows
- **无 HTTP/2 / HTTP/3** — 仍是 HTTP/1.1 + 可选 SPDY/3.1
- **学习曲线陡峭** — C 语言手动内存管理 + Kore 独特架构
- **社区较小** — ~3.7K stars，生态远不如 Node.js/Go/Python 框架
- **不适用于快速原型** — 开发效率远低于现代高级语言框架

### 适用场景

- 高安全要求的生产 API 服务（加密设备、航天、金融）
- 极高性能微服务
- 对延迟敏感的门户服务

## 2. facil.io

| 项目 | 内容 |
|------|------|
| **官网** | https://facil.io |
| **协议** | MIT |
| **最新版本** | 0.7.x（稳定版建议用 release） |
| **语言** | C11 |
| **设计范式** | 事件驱动 + 线程池 + fork 混合 |

### 概述

facil.io 是一个功能丰富的 C 网络库 / 微框架，提供 HTTP/1.1、WebSocket、Pub/Sub、JSON 解析、Mustache 模板等一体化 API。核心仅 2 个文件 (`fio.h` + `fio.c`)，易于嵌入。Ruby Iodine HTTP/WebSocket 服务端基于此项目。

### 优势

- **功能丰富** — HTTP/1.1、WebSocket、Pub/Sub、Redis 支持、JSON、Mustache 模板，内置开箱即用
- **多并发模式** — 支持单线程、多线程、混合模式（多进程 + 线程 Worker）
- **API 统一** — HTTP、JSON、Mustache 使用同一套类型/API，学习曲线低
- **易于嵌入** — 核心仅两个文件，直接复制到项目中即可
- **C10K 解决** — epoll/kqueue 事件驱动设计
- **MIT 许可** — 宽松商业友好

### 劣势

- **开发停滞** — 主分支自 2021 年以来无明显提交；作者重心转移到新的 STL 仓库
- **无 HTTP/2** — 作者曾寻求社区帮助实现 HPACK/HTTP2，未果
- **无内置 TLS/SSL** — 需要手动集成外部库
- **文档不足** — 社区反馈："列了函数签名却没说明它们如何交互"
- **主分支不稳定** — README 明确警告 master 是开发分支可能随时坏掉
- **无 Windows 支持** — 回退到 poll() 性能差
- **最新 release 距今超 5 年** — 长期维护存疑

### 适用场景

- 需要嵌入式 WebSocket/Pub/Sub 的 C 项目
- 快速搭建 C 原型（如果接受维护风险）
- 对稳定性要求不高的个人或实验项目

## 3. Ulfius

| 项目 | 内容 |
|------|------|
| **官网** | https://github.com/babelouest/ulfius |
| **协议** | LGPL 2.1 |
| **最新版本** | 2.7.15 (2025 年 10 月) |
| **语言** | C99 |
| **后端** | GNU libmicrohttpd |

### 概述

Ulfius 是一个基于 **GNU libmicrohttpd** 的轻量级 REST 框架，由嵌入式开发者创建，初衷是用于家庭自动化和树莓派等设备。内置 Jansson JSON 处理 + libcurl 客户端。它是目前嵌入式 C Web 框架中最活跃维护的项目之一。

### 优势

- **活跃维护** — 2025 年仍有更新，Debian/FreeBSD/Arch 官方打包
- **内存占用小** — 从设计上针对嵌入式设备优化
- **API 简洁** — 提供类似 Express.js 的路由/回调模型，C 语言中罕见
- **内置 JSON** — 基于 Jansson，请求/响应 JSON 处理开箱即用
- **WebSocket 支持** — 服务端 + 客户端
- **流式传输** — 大文件/大数据流低内存处理
- **FreeRTOS + LWIP** — v2.5+ 支持无 OS/RTOS 的嵌入式环境
- **自定义内存分配器** — 可以替换 malloc 族函数（适合内存调试/约束场景）

### 劣势

- **依赖链较长** — 需要 libmicrohttpd + jansson + libcurl + orcania + yder + gnutls + zlib
- **非单文件** — 相对于 mongoose/civetweb 等单文件库，集成成本高
- **线程模型局限** — 默认线程-每-连接模式，大量并发时资源消耗大
- **GnuTLS 依赖** — HTTPS 需要 GnuTLS，显著增大二进制体积
- **LGPL 许可** — 对商业闭源嵌入式产品有合规要求
- **不适合极低资源 MCU** — 32KB RAM 的 Cortex-M0 不能跑
- **内存分配器历史 bug** — v2.6.0-v2.7.6 存在自定义分配器绕过问题

### 适用场景

- Linux 嵌入式设备（树莓派、BeagleBone、Yocto、OpenWrt）
- 需要 REST API + JSON 的物联网网关
- 已有 libmicrohttpd 需要上层封装的场景
- 资源在 64MB+ RAM 以上的嵌入式 Linux

## 4. Lavandula

| 项目 | 内容 |
|------|------|
| **官网** | https://github.com/ashtonjamesd/lavandula |
| **协议** | MIT |
| **最新提交** | 2026 年 1 月 |
| **语言** | C (现代 C 风格) |
| **状态** | ⚠ **早期开发 — 不可用于生产** |

### 概述

Lavandula 是一个新兴的 C Web 框架，试图将 **Express.js/Flask 级别的开发体验** 带到 C 语言中。提供控制器/路由系统、中间件管道、SQLite 集成、内置 JSON、CLI 脚手架工具等现代特性。2025 年底在开发者社区引发热议，代码被评价为"近年来最干净、最现代的 C 代码"。

### 优势

- **开发体验极佳** — 宏 + 路由机制让 C 写 Web 服务感觉像高级语言
- **中间件管道** — 支持局部和全局中间件，实现方式优雅
- **内置 SQLite + JSON** — 无需外部依赖
- **CLI 工具 (`lavu`)** — 项目脚手架生成
- **"热重启"机制** — 开发时自动重载
- **极简依赖** — 纯 C，核心依赖极少
- **MIT 许可**

### 劣势

- **不成熟** — 仅 153 次提交，无稳定 release
- **不可用于生产** — 作者明确说明
- **性能未经充分测试** — 无公开 benchmark
- **社区极小** — 刚刚起步
- **功能有限** — 尚缺很多生产级特性（TLS 深度集成、认证等）
- **未来不确定** — 可能停止维护

### 适用场景

- **学习和实验** — 理解"现代 C Web 框架"应为何样
- **个人/业余项目** — 如果你愿意接受不稳定
- **不适合任何生产负载**

## 5. Onion

| 项目 | 内容 |
|------|------|
| **官网** | https://github.com/davidmoreno/onion |
| **协议** | Apache 2.0 / LGPL |
| **语言** | C |
| **状态** | 成熟，但近年活跃度下降 |

### 概述

Onion 是一个 C 语言 HTTP 服务器库，提供简单易用的 API 来创建 Web 应用。在早期基准测试中表现不俗（~483K req/s），但近年来活跃度明显下降。

### 优势

- **API 易用** — 相对直观的 C 接口
- **性能良好** — 历史 benchmark 表现不错（483K req/s）
- **许可靠** — Apache 2.0 / LGPL 双许可
- **文档相对完善**

### 劣势

- **不够活跃** — 近年更新频率低
- **功能有限** — 相比 Kore/facil.io 缺少高级特性
- **社区较小**
- **缺乏现代特性** — 无 WebSocket / HTTP2 / TLS 深度集成

### 适用场景

- 简单的 HTTP 服务
- 对现代特性无要求的轻度场景

## 选型建议

### 🏆 按场景推荐

| 场景 | 首选 | 备选 | 理由 |
|------|------|------|------|
| **高性能生产 API** | **Kore** | Onion | 安全纵深 + 顶级性能 + 零依赖部署 |
| **嵌入式 REST 服务** | **Ulfius** | — | 专为嵌入式设计，FreeRTOS 支持，活跃维护 |
| **实时通信/Pub/Sub** | **facil.io** | — | 内置 WebSocket + Redis Pub/Sub，原生支持 |
| **C 语言学习/实验** | **Lavandula** | — | 现代 C 风格，路由/中间件设计优雅 |
| **简单 HTTP 服务器** | **Kore** | Onion | Kore 即使简单场景也带来安全收益 |
| **Windows 部署** | **Onion** | — | 唯一对 Windows 友好且成熟的选项 |

### 一句话总结

- 要 **安全 + 性能** → **Kore**
- 要 **嵌入式 + REST** → **Ulfius**
- 要 **实时通信** → **facil.io**（接受维护风险）
- 要 **学习现代 C Web** → **Lavandula**
- 要 **Windows 兼容** → **Onion**
